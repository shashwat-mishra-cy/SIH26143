SIH26143 — Shared Team Notes & Technical Roadmap
================================================================================

1. Purpose
--------------------------------------------------------------------------------
The purpose of the SIH26143 project is to provide an end-to-end automated framework for detecting oil spills using Sentinel-1 SAR satellite imagery, estimating their spatio-temporal origin using backward ocean drift modeling, and attributing responsibility by ranking candidate vessels based on historical AIS trajectories.

2. Team Responsibilities
--------------------------------------------------------------------------------
- Rhishabh (Satellite / Computer Vision - P1):
  * Preprocessing of Sentinel-1 SAR GRD/SLC imagery (speckle filtering, terrain correction, calibration).
  * Deep learning model architectures for oil spill segmentation.
  * Training, evaluation, and inference pipelines.
  * Geometrical property extraction (spill centroid, perimeter, area, orientation, major/minor axes, GeoJSON Polygon/MultiPolygon).
  * Providing valid observation/detection timestamp from satellite metadata.

- Shashwat (Ocean / Drift - P2):
  * Receiving spill geometry (Polygon / MultiPolygon) and valid observation/detection timestamp from P1.
  * Running backward drift reconstruction using OpenDrift with surface wind forcing and ocean-current forcing.
  * Supporting irregular Polygon and MultiPolygon spill geometry inputs.
  * Running a stochastic ensemble of particles rather than assuming one exact deterministic trajectory.
  * Applying configurable horizontal diffusion.
  * Using Kernel Density Estimation (KDE) and 50% / 90% Highest Density Region (HDR) analysis to estimate probable source-support regions.
  * Performing temporal source-support diagnostic analysis across hindcast timesteps.
  * Producing a candidate source-time estimate only when evidence supports one, returning explicit indeterminate statuses (`indeterminate_flat_signal`, `indeterminate_boundary_minimum`, `indeterminate_conflicting_minima`, `insufficient_temporal_data`) when evidence is insufficient or conflicting.
  * Providing structured P2 -> P3 handoff (`DriftSourceResult`).
  * Providing particle trajectory data (particle ID, timestamp, latitude, longitude at 10-minute resolution) that P4 can visualize (downsamplable to 30-minute intervals).
  * Scientifically cautious terminology: "probable source region", "source-support region", "possible backward trajectories", "potential association", "uncertainty". P2 outputs do NOT claim an exact source point, exact release time, or proof of vessel causality.
  * Timestamp Rule: Must not invent or assume a satellite timestamp. If no valid timestamp is available, time-dependent source reconstruction and temporal AIS correlation are limited/unavailable, and P4 should clearly indicate timestamp unavailability.

- Divyansh (AIS / Analytics - P3):
  * AIS message parsing, cleaning, trajectory reconstruction, and spatial-temporal candidate vessel indexing.
  * Consuming P2 -> P3 `DriftSourceResult` handoff schema (version 1.0) from `drift/simulation/handoff.py`.
  * Spatial-temporal correlation between vessel trajectories and estimated source-support regions/time windows.
  * Probabilistic candidate vessel ranking algorithm.

- Shubh (Backend / Dashboard - P4):
  * System architecture, REST/gRPC API backend design.
  * Orchestrating execution across satellite -> drift -> AIS modules.
  * Interactive web dashboard for visualizing SAR layers, drift contours, AIS tracks, particle ensemble trajectories (downsamplable from 10-min to 30-min), and attribution reports.
  * Indicating clearly when satellite observation timestamp is unavailable.
  * System integration, deployment, and contract enforcement.

3. System Pipeline
--------------------------------------------------------------------------------
Sentinel-1 SAR
  -> Oil-Spill Segmentation (Deep Learning)
  -> Spill Geometry (Geospatial Analysis)
  -> Ocean/Wind Data (Environmental Forcing)
  -> Backward Drift/Hindcast (Particle Tracking)
  -> Probable Source Region/Time Window (Probability Polygon)
  -> Historical AIS Correlation (Spatio-Temporal Query)
  -> Ranked Potentially Associated Vessel (Attribution Score)
  -> Dashboard (Visualization & Reporting)

5. Integration Contracts
--------------------------------------------------------------------------------
- Satellite (P1) -> Drift (P2) Interface:
  Spill geometry (Polygon / MultiPolygon coordinates, centroid, area, confidence) and valid observation timestamp from satellite metadata.
- Drift (P2) -> AIS (P3) Interface:
  Implemented in `drift/simulation/handoff.py` (`DriftSourceResult`). Contains source-support geometry (50% / 90% HDR Polygons or MultiPolygons preserved without simplification), source-time candidate (or null when indeterminate), estimator status, HDR areas, ensemble particle count, and model parameters.
  *Note: Before introducing a project-wide shared schema (e.g. `shared/schemas/contracts.py`), the team should agree on the final P1->P2->P3 contract.*
- Drift (P2) -> Dashboard (P4) Visualization Interface:
  Particle trajectory data (particle ID, timestamp, latitude, longitude) produced at 10-minute intervals. P4 can downsample to e.g. 30-minute intervals for UI rendering.
- AIS (P3) -> Backend/Dashboard (P4) Interface:
  JSON schema containing ranked candidate vessels (MMSI, vessel name, distance-to-origin metric, temporal alignment score, overall confidence score).

6. Technical Decisions
--------------------------------------------------------------------------------
- Version Control: Feature branch workflow targeting `main` via PR code reviews.
- Schema Definition: Validated P2->P3 contract currently implemented in `drift/simulation/handoff.py`.
- Modular Isolation: Each subfolder (/satellite, /drift, /ais) maintains isolated logic to allow independent development and testing.

7. Dataset Notes
--------------------------------------------------------------------------------
- Satellite Data: Copernicus Sentinel-1 SAR imagery (C-band, IW mode).
- Oceanographic Data: Surface current and wind field data (e.g. ERA5 reanalysis, HYCOM ocean currents).
- AIS Data: Historical AIS message logs containing timestamped MMSI coordinates, SOG, COG.
- Note: Avoid committing large dataset files directly to Git repository. Store raw data locally in `data/` following `data/README.md`.

8. Open Questions
--------------------------------------------------------------------------------
- Target resolution for backward drift simulation grid.
- Computational strategy for high-density AIS trajectory spatial indexing (e.g. R-tree vs PostGIS vs DuckDB).
- Calibration requirements for SAR wind-shear vs actual oil slick damping signatures.
